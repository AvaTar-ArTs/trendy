# Repository Readiness Checklist

Use this checklist before submitting a repository to Trendshift or announcing it publicly.

## Positioning

- [ ] The repository has one clear primary audience.
- [ ] The first sentence says what the project does.
- [ ] The README explains the problem before listing features.
- [ ] The project is described as a product or usable system, not only as a collection of experiments.
- [ ] The repository name and description agree.

## GitHub metadata

- [ ] Repository is public.
- [ ] Default branch is healthy.
- [ ] License is present.
- [ ] Topics are specific and accurate.
- [ ] Website/demo URL is present when available.
- [ ] Social preview image is configured.
- [ ] No secrets, tokens, local usernames, or private filesystem paths are committed.
- [ ] Fork and upstream provenance are clearly documented where applicable.

## Documentation

- [ ] Clean-install instructions work.
- [ ] Quickstart takes less than ten minutes.
- [ ] A minimal example is included.
- [ ] Expected output is shown.
- [ ] Architecture diagram or pipeline explanation is included.
- [ ] Configuration and environment variables are documented.
- [ ] Limitations are stated honestly.
- [ ] Roadmap identifies the next useful milestones.
- [ ] Contributing guide exists.
- [ ] Code of conduct exists if outside contributions are expected.

## Engineering trust

- [ ] Tests or verification commands exist.
- [ ] CI runs on pull requests.
- [ ] Errors are understandable.
- [ ] Example data does not require private credentials.
- [ ] External provider calls are isolated behind adapters.
- [ ] Generated artifacts include provenance where appropriate.
- [ ] Releases contain notes and migration information.
- [ ] Forked code is labeled as upstream or adapted.

## Launch assets

- [ ] One-sentence pitch
- [ ] 30–90 second demo
- [ ] README screenshot
- [ ] Architecture diagram
- [ ] Example output
- [ ] Release notes
- [ ] Community announcement
- [ ] Technical walkthrough
- [ ] Maintainer response plan for the first week

## choTaku-specific readiness

- [ ] Canon/storyworld schema is explained.
- [ ] Character, lore, event, scene, graph, and artifact concepts have examples.
- [ ] A provider-neutral compile path works without requiring one vendor.
- [ ] Layout contracts are demonstrated.
- [ ] Continuity validation is demonstrated.
- [ ] Provenance output is demonstrated.
- [ ] Comic, manga, storyboard, or cinematic projection is visible.
- [ ] The Crimson Curse Master fixture is easy to run.
