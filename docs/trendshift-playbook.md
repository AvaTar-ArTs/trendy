# Trendshift Playbook

## 1. Understand the surfaces

Trendshift has several distinct discovery surfaces:

| Surface | What it rewards |
|---|---|
| Live/daily | Recent acceleration and current attention |
| Weekly | Momentum sustained across several days |
| Monthly | Continued interest across a longer launch window |
| Yearly | Durable adoption and repeated relevance |
| GitHub Trending history | Appearance in GitHub’s own trending snapshots |
| Repository profile | Long-term activity, history, mentions, topics, and project presentation |

A repository may be submitted and tracked without immediately appearing in a ranking.

## 2. Submit the repository

Go to [Trendshift](https://trendshift.io/), log in if requested, and use **Submit repository**. Submit the canonical public GitHub URL.

Record the date, repository, and any confirmation in [launch-log.md](../campaigns/launch-log.md).

## 3. Prepare the project before submission

Trendshift profiles commonly expose the repository’s language, stars, forks, contributors, license, topics, website, description, and trend history. Those fields are pulled from GitHub, so improve them at the source.

Minimum preparation:

- Public repository with a stable default branch
- Clear one-sentence description
- README with problem, audience, capabilities, installation, quickstart, example, architecture, and roadmap
- Open-source license
- Reproducible setup
- Working example or demo fixture
- At least one release tag
- GitHub topics that describe the actual project
- Issue templates and contribution guidance
- No accidental secrets or private paths
- Screenshots or a short demo where visuals are central

## 4. Build legitimate momentum

Useful momentum signals include:

- Real stars from interested users
- Forks used for experiments
- Issues that contain meaningful questions or bug reports
- Pull requests and merged contributions
- Releases with visible improvements
- External technical discussions and mentions
- Tutorials, demos, and integrations made by other people
- Repeat activity over several weeks

Do not optimize for a one-hour spike that leaves the repository empty afterward. Weekly and monthly surfaces reward sustained interest.

## 5. External distribution

Use a small number of relevant, high-quality announcements:

- GitHub Discussions and Releases
- Hacker News, when the project has a technical story
- Reddit communities where the project genuinely belongs
- X or LinkedIn build-in-public updates
- Dev.to or Medium technical walkthrough
- Hugging Face Spaces or model/community pages when relevant
- MCP, agent, creative-coding, comics, or story-tool communities where appropriate

Each announcement should lead with a working use case, not a request for stars.

## 6. What to measure

Track:

- Date submitted
- Release version
- Stars gained
- Forks gained
- Contributors
- Issues opened and resolved
- Pull requests
- Referral sources
- Demo usage
- Trendshift appearance
- GitHub Trending appearance
- Qualitative feedback
- Retention after the launch week

Trendshift’s exact ranking formula is not published. Treat these as observable signals, not guaranteed inputs or a formula to game.
